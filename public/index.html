        How it works

        1. Extract. Files are read in your browser (PDF via pdf.js, Word via mammoth). Project Gutenberg boilerplate is stripped.
        2. Chunk. Text is split on paragraph and sentence boundaries into ~1,000-character chunks with ~200 characters of overlap. Each chunk gets an ID like D2-C0153 (document 2, chunk 153).
        3. Embed & store. Each chunk is embedded in your browser with all-MiniLM-L6-v2 (ONNX, int8), so there is no per-page API cost. The store (chunks + vectors) is saved in your browser's IndexedDB and can be downloaded.
        4. Retrieve. Each question plus two extra phrasings is searched with embeddings (mean-centered cosine with a hubness correction) and BM25 keywords, fused with reciprocal-rank fusion, then diversified with MMR → top 8 chunks.
        5. Gate. If nothing retrieved is similar enough, the answer is “not in the sources” and the LLM is not called.
        6. Answer. The LLM gets only the 8 snippets and must return JSON: sentences, each with chunk IDs, or not_in_sources.
        7. Check. Code checks every sentence: it must have an ID, the ID must exist and have been retrieved for that question, and every number and name in it must appear in the cited chunk. Failing sentences are dropped before the story.
        8. Story. The LLM weaves the checked sentences into a story, citing IDs, and skips “not in the sources” topics. The story is checked the same way, then a second LLM pass audits each sentence against its snippets.

        Source: GitHub repo. No API keys are in the code.

        Built for MCON 368. Embeddings run locally in your browser; answers by Gemini via a Vercel function.
